playwright-e2e-mcp

The diagnosis layer for AI test-fixing: run your Playwright suite, get classified failures with the DOM at failure, verified fixes and cross-run flakiness.

● Endpoint is live:

https://playwright-e2e-mcp.vercel.app/api/mcp

It speaks MCP Streamable HTTP and can expose the same eleven tools as the stdio server:

  • run-test, get-run-status, get-failure, suggest-fix, list-tests
  • inspect-page, validate-selector
  • generate-e2e-test, compare-visual-state, diagnose-flaky, analyze-history

Verify it with a handshake (this endpoint needs its bearer token):

curl -X POST https://playwright-e2e-mcp.vercel.app/api/mcp \
  -H 'content-type: application/json' \
  -H 'accept: application/json, text/event-stream' \
  -H 'authorization: Bearer <token>' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"curl","version":"1.0"}}}'

This hosted endpoint is for clients that only accept remote connectors (ChatGPT custom connectors, remote MCP clients). It requires a bearer token: a request without Authorization: Bearer <token> is answered 401 {"error":"unauthorized"}, and with it all eleven tools are served. (A self-hosted bridge started without PW_MCP_HTTP_TOKEN instead serves just the read-only tools, list-tests, get-failure and analyze-history.)

What it can and cannot do: this endpoint runs in a cloud function, so it can inspect and validate public URLs, but it cannot see your repository, your localhost or your test suite. To run and fix your own tests, run the server next to your code: npx -y playwright-e2e-mcp (see the README for one-line installs).
